HOP · the orchestrator

One binary runs the cluster.

Agent, leader and HTTP API in one Go binary — no database, no sidecars. Jobs with health checks, restarts and priorities; an HMAC-signed API; leader election on a CAS lock with cluster state in any S3 bucket — a node that reboots brings its own jobs back. And it runs every kind of workload: processes, containers, whole machines.

Every workload. Three drivers, one job spec.

exec

Plain processes with isolation and limits, on the Linux and macOS machines you already have. Adopt HOP today without touching your OS choice.

Docker

Your existing containers, unchanged — same job spec, same API. HOP schedules and supervises; Docker stays the runtime you know.

hop → HopOS

The workload the others can’t: apps without an OS underneath. Whole cores, hardware cages, per-app cpu/mem/temp telemetry with no agents or exporters — see the HopOS story.

One job spec, every machine in the cluster. A job can carry several artifacts, each with a match on node attributes, and every agent downloads the first one that fits. So one spec sends the arm64 build to a Pi and the riscv64 build to a €15 RISC-V board — no per-node config, no duplicated job. The infrastructure for the metal side is already published that way: a load balancer, cluster DNS, a Prometheus exporter and Cloudflare’s own tunnel, as signed slot images you point a job at.

State lives in any S3 bucket — one committed object is the whole database, and the leader itself fails over on the same lock (~60 s). The lock is plain S3 conditional writes — If-None-Match: * claims the lease, If-Match: <ETag> renews it; the ETag is the proof no one else wrote in between (how it works). Reboot a node, it reloads its own jobs: 126/126 back in 17.4 s after a hard power cut, zero resubmits, measured on real hardware. count: -1 runs a job on every node in the cluster. And the node itself stays stateless — state on S3, not on metal: nothing to back up, nothing to drift.

What HOP is not

Not Kubernetes: no CRDs, no operators, no YAML sprawl — and none of the ecosystem either. Will it have bugs? All software does. The difference is the setup: ~7,550 KISS lines that fit in a single AI context window — you can audit the entire orchestrator in one sitting, human or machine. And its go.mod lists three modules, zero third-party — the same foundation HopOS runs on: lean (~5,000 of it linked) and the ~1,000-line S3 lock. No raft library, no etcd, no web framework, no net/http. It has been running our own production workloads for months. We eat here first.
