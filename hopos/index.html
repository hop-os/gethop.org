HopOS · the Go-only OS

Compute, with fewer moving parts.

A Go operating system built around a small job: give an app memory, give it compute, connect it, and reclaim its resources when it finishes. Run directly on ARM64 and RISC-V, from a small board to a many-core server.

The execution model

Your app owns its memory.
You choose how it uses the cores.

Give a compute job dedicated cores, including multiple cores for one Go runtime. Let explicitly trusted apps share a core cooperatively when that fits the workload. Each resident keeps its own memory partition.

The framework has one lifecycle: allocate, place, run, wait, wake, stop and release. Memory is reusable after execution has ended; a shared core stays available to its remaining residents.

What it can do

A small framework. Useful capabilities.

01 / Compute

Dedicated or deliberately shared.

Give a busy app whole cores. Put trusted, intermittent workloads together through a sharegroup. Cooperative sharing uses the same lifecycle and preserves separate memory partitions.

02 / Updates

Flip the kernel. Keep the apps.

FLIP replaces the running kernel and adopts its residents. Apps keep running in their existing memory, with their network connections. The update uses a borrowed memory window; old pool windows become reusable after handover.

03 / Architecture

One framework across two ISAs.

The ownership rules stay the same on ARM64 and RISC-V. Architecture code supplies protection, context switching and core control; boards supply boot and device wiring.

04 / Go

Go from the service to the device.

Apps, orchestration, networking and drivers are written in Go, with small assembly boundaries for hardware entry and switching. TamaGo supplies the bare-metal Go runtime. Existing Go packages can come along when their platform needs fit.

FLIP has retained resident TCP connections across repeated ARM updates and four consecutive RISC-V updates. The LicheeRV candidate returns to its original kernel window on a second flip and then runs cloudflared, Stulp and its plugins together on one app core. See the recorded verification scope. One path for work

One network entry. One doorbell per resident.

The app’s system calls travel over the same network path as its other traffic. One caller at a time serializes those calls. The node routes the request to the service that owns the device.

Publish first. Then ring.

The pump arms its doorbell and rechecks for pending work before sleeping. A notification tells the resident to look; the ring holds the actual work. Trusted neighbors get their turn when a resident yields.

The IRQ goal is equally small.

One network IRQ feeds this receive path. QEMU virt has the IRQ implementation; physical boards currently poll. Per-board network IRQ integration is the next power-efficiency step. This describes network reception; architecture timers still handle their own duties.

Keep one implementation of the common rules and small hardware-specific boundaries. The per-board headless metal source selection is approximately 14.6–17.9k lines, including that shared code. Lean adds 10,744 selected networking and support lines.

What these numbers include scope and provenance

Counted from the v2.2.2 source with tools/loc.go on 6 September 2026: nonblank, noncomment Go and assembly lines in the selected source files. These are source-file counts, not a count of every linked dependency or executed instruction. Go’s runtime and standard library, TamaGo, HOP and other dependencies are outside the metal/Lean figures; desktop apps are separate.

The approximately 4000 MB/s M4 write result was reported by the developer. Workload, cache policy and durability conditions were not recorded in the review, so it is an indicative measurement rather than a cross-platform benchmark.

Where it runs

From a tiny board to a many-core server.

Apps are built once per architecture, not once per board. HopOS supplies the board-specific boot and drivers underneath. On UEFI machines and the Mac mini M4, its own bootloader takes over from the platform firmware — no GRUB in between.
