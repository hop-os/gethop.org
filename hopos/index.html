HopOS · the Go-only OS

Give every Go app its own piece of the machine.

HopOS boots directly on ARM and RISC-V hardware. No Linux, no VM and no container layer. It turns a board into a small, stateless application node where each app gets physical cores and hardware-fenced memory.

What it is

An application node, not a general-purpose computer.

Compile a Go service for HopOS and hand HOP a signed image plus a small job spec. HopOS downloads it, gives it cores and memory, connects it to the network and keeps it inside that boundary.

That narrow job is the point. There are no users, packages, shell services, container daemons or local state to manage.

What it does differently

Three design choices change the whole machine.

01

Remove the shared kernel.

A normal server puts every workload on one large kernel. HopOS keeps the OS outside an app’s address space and exposes an ABI of ten operations instead. There is simply much less shared machinery to attack, patch or configure.

smaller trusted surface

02

Give resources away whole.

By default, an app owns physical cores and a memory partition. ARM stage-2 translation or a RISC-V PMP whitelist forms the boundary in silicon. Trusted apps can opt into sharing; strangers never do by accident.

predictable isolation

03

Rebuild nodes instead of repairing them.

The boot medium carries HopOS and a few lines of config. Apps and cluster state live in object storage. After a power cut, the node reconstructs itself from committed state instead of trusting whatever happened to remain on disk.

no machine drift

The useful constraint

HopOS does less. On purpose.

A good fit

  • Go services that deserve dedicated resources
  • Edge boxes and single-purpose appliances
  • Small clusters that should be replaceable, not maintained by hand
  • Workloads where a reviewable stack matters

Not what it is

  • Not a Linux distribution
  • Not a Docker or Kubernetes replacement
  • Not a general-purpose desktop
  • Not a place for state that exists on only one machine

Need both? A HOP cluster can mix HopOS nodes with Linux machines. Run caged Go apps on HopOS and keep Docker or non-Go workloads on Linux, behind the same job API.
